# V2 模型分组监控

`/monitor` 使用站点真实调用的被动汇总。默认展示最近 24 小时，以平台、模型和分组分别统计；专用生图模型也独立展示。未调用和样本不足保持灰色，缺少缓存或流式首字数据显示 `—`。

## 状态与耗时

- 成功率是成功调用数除以全部调用数，按错误率阈值单独判色。忽略错误类别只影响上游健康评分，不会提高真实成功率。
- 综合评分延续错误、延迟、缓存权重；参与评分的异常指标会使综合状态至少为“波动”，避免被平均成正常。
- 对话模型使用首字 P50；生图使用生成耗时 P95，缺少时依次回退 P90、P50。平均耗时仍单独展示。
- 生图默认关注阈值 60000 ms、异常阈值 180000 ms。管理员在“监控设置”中可针对平台、精确模型名、分组设置覆盖规则。更多匹配条件优先；同等条件数按分组、模型、平台的顺序优先。
- 页面同时检查汇总计算时间与数据水位。超过 `max(180 秒, 3 × 汇总频率)` 标记数据过期，保留历史值和时间条，当前健康计数显示 `—`。接口请求失败与汇总过期分别提示。

## 详情与偏好

点击分组打开完整窗口详情；点击时间格或用方向键选择后按 Enter，打开该统计区间的指标和错误分类。接口 `start`、`end` 为 RFC3339，必须同时提供、按当前范围的汇总粒度对齐，且在近 30 天内。结束时间不包含在区间中。请求仍执行原有管理员/用户分组权限校验。

普通用户仅查看比例与延迟；管理员还能查看请求数量和脱敏错误摘要。用量日志入口使用现有日期筛选，进入后可继续筛选模型和分组。

支持异常优先、成功率升序、耗时降序和名称排序。收藏置顶，也可仅看收藏。筛选、展示方式和收藏保存在当前浏览器的当前用户命名空间；显式 URL 参数优先于已保存偏好。

## 告警与恢复

管理员从“告警设置”进入运维监控，在告警规则中选择 V2 成功率、缓存率、首字 P50 或生图生成耗时。每条规则必须指定平台、精确模型和分组，配置最小样本、连续异常观察次数、持续分钟数、连续恢复次数与冷却时间。成功率/缓存率阈值单位为百分比，延迟单位为毫秒。

每个新的汇总水位最多推进一次观察。异常必须同时满足连续观察次数与持续时长；数据过期、样本不足、缺少适用指标或覆盖不完整不会触发，也不会误判恢复。检查点复用现有运维事件表，内部待确认事件不会出现在事件列表。重启可续接状态，通知领取与状态更新使用规则锁和版本检查。

新建 V2 规则默认关闭且邮件通知关闭；启用后仍受原运维监控、邮件接收者、告警级别和静默规则限制。恢复通知需单独勾选。异常和恢复使用独立的通知去重标识，无新增通知渠道、数据库表或主动探测流量。

本地演示服务仅用于界面预览：模型、用量、错误摘要均为合成数据，配置只保存在内存中，不评估告警也不发送邮件。
